Everything is a loop

A game is two loops running at once. One runs inside the machine, sixty times a second, taking input and producing pixels and sound. The other runs inside the player, at the speed of thought, taking feedback and producing intent. Design is the craft of shaping the second loop. Programming is the craft of making the first one fast, correct, and honest. This document covers both, from first principles to the details that only show up in production.

Every problem in this manual is a defect somewhere in this circle. Unresponsive controls break the input arc. An unreadable HUD breaks feedback. An unfair difficulty spike breaks the mental model. A frame time spike breaks all five at once.

When a game is not fun and nobody can say why, walk the loop one arc at a time and ask which arc is lying to the player.
